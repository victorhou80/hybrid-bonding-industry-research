## 已冻结的核心研究结论

### 1. 技术路线必须分层

- **Direct Hybrid Bonding：** 直接介质/金属界面键合的 3D 互连路线；必须区分 W2W、D2W/C2W 与其各自的 KGD、对准、吞吐、缺陷、可靠性和返修约束。
- **TSV：** 穿硅垂直互连，不等于 direct Hybrid Bonding。TDV/nTSV 的公开研究也不等于传统 TSV 或 HBM TSV。
- **micro-bump / TCB：** 是与 direct HB 不同的互连路线；不可借用彼此的 pitch、overlay、良率或产能数据。
- **2.5D / RDL / interposer：** 是横向封装集成层，不能被当作内部 HB/TSV 的同义词。
- **HBM：** 是高带宽存储产品与生态，不是键合方式。HBM、TSV + micro-bump/TCB、2.5D/RDL、3D NAND/CIS 与 direct HB 需要分别统计产能、良率、销量和收入分母。

### 2. 密度与精度记录必须保留对象

公开一手来源可支持平台、工具、研究或 test vehicle 在其各自对象下的声明；它们不自动支持某个未披露产品的实际 pitch、post-bond overlay、有效 data I/O、good-link density、yield、WPM、客户或出货。由 pitch 做出的几何站点密度只能标为 **A6 名义换算**，而不是产品或市场数据。

目前强度最高的公开技术记录包括：

- TSMC SoIC 的公开平台表述：bond pitch 从 `sub-10 µm rule` 开始，3 nm chip stacking 在 2025 年进入 volume production（**A2 平台状态**，不是 SKU 出货）；
- imec/EVG 的 300 mm W2W **test vehicle**：200 nm Cu pad pitch、全片 100% die 的 post-bond overlay vector `<40 nm`（**A3 研究/test vehicle**，不是客户产品、量化 yield 或实际 shipped die）。

更完整的数字对象、来源链接和不可外推项见 `source-map.md` 及既有公开证据包。

### 3. A1 实际出货闭环仍为空缺

在本研究已复核的公开范围内，尚未建立一条同时含有以下要素的 Hybrid Bonding / TSV 证据链：

`明确 pitch 或 overlay → 具体产品 SKU → 客户/验收 → 明确期间交付或收入`

此状态记作 **A1-Ø**。它的含义是“公开、可审计的闭环尚未建立”，不是技术、项目、产能或市场为零。

### 4. 供应链应按模块与证据状态建图

可识别的关键模块包括：

`3D EDA/PDK/IP → 逻辑/存储晶圆 → CMP/清洗/表面活化 → 对准/键合 → 临时键合/减薄/背面互连 → 量测/缺陷检测 → KGD/测试/可靠性 → 封装/基板/热 → 系统资格与客户验收`

模块能力、设备页面、历史工程主题、计划、订单新闻或公司级收入都不能确认任何特定产品的供应关系。公开版只能使用“模块能力/待验证对象”口径，直到产品—工艺—客户—良率—产出/收入形成同一链条的 A1 闭环。

所有“产能”须注明位于下列六层中的哪一层：

`设计/铭牌能力 → 已安装能力 → 客户认证可用能力 → 良率后的有效能力 → 实际产出/出货 → 利用率`

### 5. 算苗 / 中科声龙 / 专利的正确边界

- `CN121920305A`、`CN121925162A`：可作为算苗相关的计算—存储 Hybrid Bonding / 三维布局架构主张；不能据此证明实际 Cu–Cu、W2W/D2W、实物层数、性能、量产、供应商、客户或出货。
- `CN121034366A`：DRAM 访问控制/调度主题，**不是物理 Hybrid Bonding 专利**。
- `CN219040074U`：可作为中科声龙历史存储—数据处理 Hybrid Bonding 技术主题线索；权属、转让、许可及其与算苗的关系必须逐件以 CNIPA 和授权材料核验，不能自动计入算苗资产或产品。
- 历史 `Tb/s` 规划、公开 `TB/s` 带宽和 `GB` 容量必须按产品、单位、测试条件和时间分开；不得因数字相近而互证或合并。

## 恢复研究时的强制门槛

恢复后，先做下列步骤，再继续任何市场结论或 GitHub 增量发布：

1. 以技术、供应链、商业/权属三份独立审阅为输入，对总草案每条补齐显式 `证据等级`、`可支持` 与 `不可支持` 字段；
2. 生成正式 `debate_50_rounds.md`、`final_verdict.md` 和发布安全审计，而不是把 `draft` 改名；
3. 对任何新增公开网页资料，通过 Codex 内置浏览器再次确认网页对象、时间、原句和不可证明项；
4. 将 50 条正式版与本快照中的公开摘要做敏感词、来源、单位、链接、Markdown 和 Git 差异检查；
5. 仅在正式审计完成后，再选择性发布新的脱敏版。不要上传本地原始 ASIC 目录或三路内部审阅全文。
